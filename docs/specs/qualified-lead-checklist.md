# Чек-лист відповідності ТЗ «Оплата за кваліфікований лід»

Звірка прототипу з `docs/specs/qualified-lead.md`. Оновлюється після кожного кроку.
Останнє оновлення: крок Б2 (сторінка консультанта), 3 жовтня 2026.

Позначки:
- ✅ зроблено в прототипі
- 🟡 зроблено частково (що саме бракує — у примітці)
- ⬜ ще не зроблено
- 🔧 лише контракт для бекенду: у прототипі без сервера це не реалізується

Де що лежить:
- `index.html` — застосунок агента
- `consultant.html` — сторінка консультанта; вкладка «Admin» буде на кроці Б3

Обидві сторінки ділять дані в одному браузері, тож можна зіграти обидві ролі.

## Критерії кваліфікованого ліда

| Пункт ТЗ | Стан | Де / примітка |
|---|---|---|
| 1. Згода: галочка агента + підтвердження клієнтом | ✅ | Агент: обов'язкова галочка на кроці 3. Консультант: «Consent received on WhatsApp», «Copy consent link», статус і спосіб згоди. Сторінка згоди для клієнта — 🔧 |
| Для згоди зберігаються спосіб, час, номер, версія тексту | ✅ | `q.method`, `q.consentAt`, телефон ліда, `q.consentTextVersion`; також `q.attestedAt` (галочка агента) |
| 2. Оцінка Yes / Borderline: DBR ≤ 50% і мінімальний внесок | 🟡 | Консультант: DBR і мінімальний внесок за статусом, з можливістю виправити. Агент: лише DBR, внесок обмежений повзунком — звірити на кроці Б4 |
| 3. Документи: позначка консультанта «Documents received» | ✅ | Три пункти (паспорт, Emirates ID або віза, довідка про дохід). Трекер 6 документів агента не змінено |
| 4. Розмова з консультантом → «Confirm qualification» | ✅ | Кнопка ставить 4-й пункт чек-листа |
| Ліди через посилання / QR: згода в анкеті, ті самі умови | 🟡 | Демо-ліди з позначкою «Via agent link» і згодою з анкети є. Сама анкета клієнта — 🔧 |
| Дубль (телефон, email, Emirates ID за 90 днів) — не кваліфікується | ⬜ | Автоматична перевірка дублів при поданні — крок Б4. Консультант уже може відхилити з причиною «Duplicate client» |
| Клієнт, що вже працює з Lenty напряму | 🔧 | Потрібна база клієнтів Lenty |

## Статуси ліда і виплати

| Пункт ТЗ | Стан | Де / примітка |

## Критерії приймання з ТЗ

- [x] Бонус нараховується лише після «Підтвердити кваліфікацію», коли є згода, оцінка «так» або «межа» і позначка про документи.
- [x] Новий агент отримує AED 150 за кожен з перших 3 кваліфікованих лідів, далі — AED 100.
- [ ] Дубль клієнта відхиляється автоматично, бонус не створюється. *(Б4)*
- [x] 11-й лід агента за місяць кваліфікується, але без бонусу; агент бачить повідомлення про ліміт.
- [x] Основна комісія за закриту угоду не змінюється від бонусів.
- [x] Лід через посилання або QR-код закріплюється за агентом і дає бонус за тими самими умовами. *(у прототипі — на демо-лідах; анкета клієнта — бекенд)*
- [x] Ліди без кваліфікації переходять у «Прострочено» через 14 днів.
- [x] Зміна суми в налаштуваннях не впливає на вже нараховані бонуси. *(сума зберігається на ліді й на бонусі)*
- [x] Усі тексти функції — англійською, з файлів перекладів.
- [ ] Вимкнення `lead_bonus_enabled` прибирає всі елементи промо-шару без релізу. *(у прототипі — `?promo=0`; перемикач — Б3)*
- [x] Лід, поданий до вимкнення, отримує бонус, якщо кваліфікується протягом 14 днів; лід, поданий після, — ні.
- [ ] Після дати `lead_bonus_ends_at` програма вимикається автоматично. *(перевірка дати при поданні є; перемикач і дати в адмінці — Б3)*
- [x] Без галочки агента подання не відправляється; перша умова виконується лише після підтвердження згоди самим клієнтом.
- [x] Ліди, подані після 30 листопада 2026, бонусу не отримують; подані раніше зберігають право протягом своїх 14 днів.
- [x] Лід з позначкою ризику або від агента з `bonus_suspended` кваліфікується, але бонус має статус on_hold. *(схвалення / скасування адміном — Б3)*
- [ ] Екрани агента відповідають стіні «До / Після» в обох станах. *(звірка — Б4)*
- [x] Наявний потік подання й банківських етапів працює без змін. *(49 варіантів екранів агента збігаються до і після кроку Б2)*
