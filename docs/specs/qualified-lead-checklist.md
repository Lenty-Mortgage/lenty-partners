# Чек-лист відповідності ТЗ «Оплата за кваліфікований лід»

Звірка прототипу з `docs/specs/qualified-lead.md`. Оновлюється після кожного кроку.
Останнє оновлення: крок Б5 (узгодження правил двох сторінок), 3 жовтня 2026.

Позначки:
- ✅ зроблено в прототипі
- 🟡 зроблено частково (що саме бракує — у примітці)
- ⬜ ще не зроблено
- 🔧 лише контракт для бекенду: у прототипі без сервера це не реалізується

Де що лежить:
- `index.html` — застосунок агента
- `consultant.html` — сторінка команди Lenty: вкладки «Qualification» (консультант) і «Admin»

Обидві сторінки ділять дані в одному браузері, тож можна зіграти всі ролі. Налаштування адмінки одразу змінюють застосунок агента. Сторінки зі скриншотами (`?screen=…`) їх ігнорують, а `?promo=0` там примусово вимикає програму.

## Критерії кваліфікованого ліда

| Пункт ТЗ | Стан | Де / примітка |
|---|---|---|
| 1. Згода: галочка агента + підтвердження клієнтом | ✅ | Агент: обов'язкова галочка на кроці 3. Консультант: «Consent received on WhatsApp», «Copy consent link», статус і спосіб згоди. Сторінка згоди для клієнта — 🔧 |
| Для згоди зберігаються спосіб, час, номер, версія тексту | ✅ | `q.method`, `q.consentAt`, телефон ліда, `q.consentTextVersion`; також `q.attestedAt` (галочка агента) |
| 2. Оцінка Yes / Borderline: DBR ≤ 50% і мінімальний внесок | ✅ Б4.2 | Однакове правило в агента і консультанта: DBR ≤ 42% → Yes, ≤ 50% → Borderline, інакше No; внесок нижче мінімуму (15% / 20% / 40% для UAE National / Resident / Non-resident) → No з поясненням. Консультант може виправити оцінку |
| 3. Документи: позначка консультанта «Documents received» | ✅ | Три пункти (паспорт, Emirates ID або віза, довідка про дохід). Трекер 6 документів агента не змінено |
| 4. Розмова з консультантом → «Confirm qualification» | ✅ | Кнопка ставить 4-й пункт чек-листа |
| Ліди через посилання / QR: згода в анкеті, ті самі умови | 🟡 | Демо-ліди з позначкою «Via agent link» і згодою з анкети є. Сама анкета клієнта — 🔧 |
| Дубль (телефон, email, Emirates ID за 90 днів) — не кваліфікується | ✅ Б4.1 | Серед **усіх** лідів системи, зокрема інших агентів. Телефон і email — одразу при поданні (агент бачить «Not qualified · Duplicate client»). Emirates ID агент не вводить, тому він перевіряється, коли консультант відмічає «Documents received». Дублем вважається лише лід, поданий **після** іншого (в межах 90 днів); ліди, вже відхилені як дублі, не враховуються |
| Клієнт, що вже працює з Lenty напряму | 🔧 | Потрібна база клієнтів Lenty |

## Крок Б5 — узгодження правил двох сторінок (3 жовтня 2026)

Правила в прототипі записані двічі: в `index.html` і `consultant.html`. Дві розбіжності виправлено; у робочій версії правила рахує лише сервер (ТЗ, «Як передати в розробку», п. 7).

| Розбіжність | Було | Стало |
| --- | --- | --- |
| Дата кінця програми в рішенні про бонус (`consultant.html`, `decideBonus`) | Бралася з початкових налаштувань (`ADMIN_DEFAULTS`), зміна дати в адмінці не враховувалась | Береться з налаштувань адмінки (`PROGRAMME_END`) |
| Пошук дублів в агента (`index.html`, `findDuplicate`) | Без Emirates ID і без правила «дублем буває лише пізніший лід» | Те саме правило, що в консультанта: телефон, email, Emirates ID; лише лід, поданий раніше в межах 90 днів; ліди, відхилені як дублі, не враховуються |
